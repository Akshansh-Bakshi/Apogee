# SYNTHETIC next-topic dataset V2

All records and usefulness targets are fictional. Apogee currently has no real next-topic
recommendation feedback. The labels are generated by a declared synthetic rubric; they are not
human preferences, empirical ground truth, or reliable labels. Any future model trained on them
would measure imitation of this rubric only.

V2 preserves taxonomy `apogee-technical-v1`. The feature contract is defined by
`extract_candidate_features` in `ml/synthetic_next_topic_v2.py`, and the generator invokes that
same function for every generated candidate. It accepts a map of topic assignments and
event-derived aggregates: distinct assigned pages, visits, and latest visit timestamp. A live
adapter in `ml/next_topic_temporal.py` scopes assignments/events to one user and excludes events
whose occurrence or database creation is later than the chosen `as_of` timestamp. It also
requires page and assignment availability timestamps for retrospective use. `last_seen_at` is
the maximum eligible `BrowsingEvent.occurred_at`; null means
no eligible visit. Recency is nonnegative days from `as_of`. Page and visit counts are separate.
Graph features use only frozen direct prerequisite edges and assigned topic IDs. No text, user
goal, narrative, session inference, future event, page ID, model score, or label enters features.

## Feature contract

`candidate_topic_id`; candidate distinct page and visit counts; nullable recency; candidate
observed flag; observed topic breadth; total assigned pages and eligible visits; repeat-visit
ratio; candidate page and visit shares; prerequisite count; observed and missing prerequisite
counts; prerequisite evidence category; graph-gap flag (candidate has under two pages while any
direct dependent is observed); and direct-extension flag (at least one prerequisite topic is
observed). No `exploration_state` feature is included. All count features are user-scoped and
computed as of one timezone-aware timestamp.

## Dataset and split

The seed `20261116` generates 360 scenarios across 36 families, with ten varied states per family.
Each scenario has all eight candidate topics (2,880 rows). Families are assigned wholesale to
20 train, 6 validation, and 10 frozen test families (200/60/100 scenarios). The V2 test split is
new and unrelated to V1. This is still synthetic data; 10 test families do not establish real-user
generalization. The generator uses random activity states, while synthetic targets follow a
separate branch-based rubric with deterministic ambiguity. This is not independent preference
judgment; report rubric imitation explicitly.

## Reproduction

```powershell
python -m ml.synthetic_next_topic_v2
python -m pytest ml/tests/test_synthetic_next_topic_v2.py
```

The output directory contains scenario and candidate JSONL, split manifests, aggregate label
statistics, and checksums in `manifest.json`. It is separate from V1. The V2 blinded review sheet
must be generated before human review and its answer key stored separately; reviewers should not
see synthetic targets.

## Limitations

The read-only aggregation adapter and a local offline trained model were added in Prompt 24.
Neither is connected to the live API. Features are structurally derivable from existing
assignments/events and graph data, but V2 targets remain authored rules.
The label rubric intentionally uses activity and prerequisite evidence, so a ranker may simply
learn those rules. Training can proceed only as a synthetic rubric-imitation experiment. Live
integration or claims about usefulness require independently collected human judgments based on
explicit goals and the exact production feature contract.
