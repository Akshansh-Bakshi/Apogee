-----------

(APOGEE-day1.zip, 44 files) with the Day 2 delta (APOGEE-day2-delta.zip, 21 files:

architecture: (a) client-side capture via a Chrome MV3 extension, and (b) backend

was introduced. `backend/app/api/v1/capture.py`'s route, request/response model
names, and status codes are unchanged from Day 2; only its docstring and the
schema/response it references were extended.

8. Known limitations
---------------------
- No pytest/Docker/PostgreSQL execution of any backend test in this session
  (see section 6) — this includes the new PageChunk persistence, chunk
  replace-on-recapture, and rollback tests, which are written but unverified
  against a real database.
- No Chrome execution of the extension itself.
- Manual capture only; no autonomous/always-on capture.
- `manifest.json` host_permissions are static (127.0.0.1:8000, localhost:8000);
  changing the configured API base URL to a different origin in Settings also
  requires updating manifest.json.
- No PII/secret redaction of captured text; cleaning is structural only
  (whitespace, boilerplate lines, blank-line collapsing, a minimum-length
  floor) — see docs/privacy.md.
- `pages.extracted_text` remains an unused Day 1 placeholder column; real
  extracted text lives in the new `page_chunks.text`.
- Chunk size/overlap are process-wide constants in app/core/content.py, not
  configurable per request.
